\begin{abstract}
Deploying Retrieval-Augmented Generation (RAG) across geographically distributed, heterogeneous edge--cloud infrastructures introduces fundamental stage placement trade-offs. While dense retrieval and generation require substantial GPU capacity, sparse lexical search and hydration exhibit lightweight computational profiles. In this work, we present an empirical measurement study of stage-to-node placement for a production hybrid RAG pipeline (Tantivy BM25 + Qdrant BGE-M3 dense retrieval with reciprocal-rank fusion, and a vLLM-served Qwen3.8-27B generator) across commodity hardware connected over WireGuard links with bidirectional \texttt{netem} latency (0--80~ms RTT). Based on a 2{,}880-record confirmatory benchmark, our measurements reveal two core systems insights: (1) time-to-first-token (TTFT) is essentially flat across WAN RTTs ($\approx$0.95~ms of TTFT per ms of RTT) because identifier-sized boundary payloads decouple transmission delay from payload bulk; and (2) KV-cache state dominates latency variance, with cold-prefix TTFT ($\approx$1.7~s) reaching $2.8$--$3.2\times$ warm-state latency ($\approx$0.55~s). Exploiting this structure, we introduce \textbf{SPHP} (Speculative Progressive Hydration \& Prefill), which pipelines retrieval by launching a masked speculative prefill on the generation host using a provisional sparse hint while dense retrieval is in flight. SPHP achieves a measured hit rate of $h=0.900$ (95\% CI $[0.883, 0.914]$), cutting cold TTFT by 23.7\%--27.6\% across all WAN regimes (Holm-FWER $p \le 0.0008$, Cohen's $d=-1.29$ to $-1.57$) while bounding answer divergence within decoding stochasticity. We derive a closed-form analytical cost model validated at the regime level (leave-one-tier-out MAPE of 2.15\% cold / 4.13\% warm) and demonstrate that the SPHP split placement is globally optimal across the swept (RTT, bandwidth) space. Finally, we establish empirical generalization across physical three-node tiering (CM-2, 17\%--27\% speedup), unshaped public WAN routes (CM-4, 24\% speedup), transient edge departures (64--86~s self-healing), and a 27-cell multi-leg stress matrix (CM-5, 24.7\% mean speedup).
\end{abstract}

%  I. INTRODUCTION

\section{Introduction}
\label{sec:intro}
Retrieval-Augmented Generation (RAG) grounds large language models (LLMs) in external factual corpora \cite{lewis2020rag,guu2020realm,borgeaud2022retro,gao2024ragsurvey}. Modern high-accuracy pipelines deploy \emph{hybrid} architectures combining lexical sparse retrieval (BM25 \cite{robertson1994bm25}), semantic dense retrieval over dense vector embeddings \cite{karpukhin2020dpr,chen2024bge}, reciprocal-rank fusion (RRF \cite{cormack2009rrf}), passage hydration, and transformer generation under optimized engines like vLLM \cite{kwon2023vllm}.

Transitioning hybrid RAG from monolithic datacenters to geo-distributed edge--cloud fleets exposes a fundamental \emph{placement dilemma}. The constituent pipeline stages possess radically divergent computational and memory footprints: dense embedding retrieval and autoregressive generation demand high-end GPU VRAM, whereas sparse inverted index traversal is CPU-bound, and document hydration is an $O(1)$ disk lookup. Although deep neural network (DNN) layer partitioning \cite{kang2017neurosurgeon,banitalebi2021autosplit} and LLM phase disaggregation (prefill vs.\ decode) \cite{patel2024splitwise,zhong2024distserve,janus2025} have been examined for single models, the systems principles governing multi-stage hybrid RAG placement across wide-area networks (WAN) remain unexplored.

We organize our empirical inquiry around three central systems questions:
\begin{itemize}
    \item \textbf{RQ1 (Placement Trade-offs):} How should hybrid RAG stages be partitioned across edge and cloud nodes, and how sensitive is time-to-first-token (TTFT) to wide-area latency?
    \item \textbf{RQ2 (Topological Resilience):} What performance degradation and recovery dynamics emerge when edge nodes experience packet loss or transient disconnections?
    \item \textbf{RQ3 (Predictive Placement):} Can an analytical cost model accurately predict regime-level latency and guide optimal placement across arbitrary WAN conditions?
\end{itemize}

To answer these questions, we deploy a fully instrumented, multi-node testbed running against the 8.84M-passage MS~MARCO benchmark \cite{bajaj2018msmarco}. Our contributions are:
\begin{itemize}
    \item \textbf{C1 (Factorial Measurement):} We conduct a 2{,}880-record confirmatory campaign across four WAN regimes (0, 15, 40, 80~ms RTT) under bidirectional \texttt{netem} shaping. We show that TTFT is essentially flat in network latency ($\approx$0.95~ms/ms sensitivity) due to identifier-sized boundary payloads, whereas KV-cache state dominates latency variance: cold-prefix TTFT ($1.65$--$1.72$~s) is $2.8$--$3.2\times$ warm TTFT ($0.51$--$0.59$~s) (\S\ref{sec:characterization}).
    \item \textbf{C2 (SPHP Mechanism):} We propose and evaluate \textbf{SPHP} (Speculative Progressive Hydration \& Prefill). By pre-streaming a provisional sparse hint across the WAN, Node~A overlaps masked LLM prefill with dense retrieval. SPHP achieves a 0.900 hit rate, cutting cold TTFT by 23.7\%--27.6\% across all RTT tiers (Holm-FWER $p \le 0.0008$, Cohen's $d=-1.29$ to $-1.57$) with answer drift bounded to decoding stochasticity (\S\ref{sec:sphp}).
    \item \textbf{C3 (Validated Analytical Model):} We formulate a closed-form placement cost model validated via leave-one-tier-out cross-validation (regime MAPE 2.15\% cold / 4.13\% warm for baseline P2; 6.42\% cold for SPHP). Crossover analysis across 35 swept (RTT, bandwidth) cells shows that SPHP split placement is globally optimal (\S\ref{sec:costmodel}).
    \item \textbf{C4 (Generalization \& Artifacts):} We establish empirical validity across physical three-node clusters (CM-2, 17\%--27\% speedup), live unshaped public internet routes (CM-4, 24\% speedup), transient edge outages (64--86~s self-healing), and a 27-cell multi-leg stress matrix (CM-5, 24.7\% mean speedup). All benchmarks, indices, and analysis tools are open-sourced (\S\ref{sec:generalization}).
\end{itemize}

\section{System Architecture \& Topologies}
\label{sec:architecture}

\subsection{Physical Testbed Deployment}
The experimental testbed couples heterogeneous physical machines over point-to-point WireGuard tunnels \cite{donenfeld2017wireguard}:
\begin{itemize}
    \item \textbf{Node~A (Cloud Generation Host):} An AMD Ryzen workstation equipped with an NVIDIA RTX~3090 GPU (24~GB VRAM) running vLLM \cite{kwon2023vllm} with the Qwen3.8-27B model \cite{qwen38hf2026}, quantized to W4A16 via AutoRound \cite{autoround2024}. Node~A hosts an indexed SQLite database containing the complete 8.84M-passage MS~MARCO corpus \cite{bajaj2018msmarco} for $O(1)$ passage hydration. Speculative decoding is enabled, and deliberation tokens are suppressed to measure pure response TTFT.
    \item \textbf{Node~B (Edge Retrieval Gateway):} An Intel Core i7-10750H laptop with an NVIDIA GTX~1660~Ti GPU (6~GB VRAM), hosting a Tantivy BM25 sparse index over the 8.84M passages, a BGE-M3 dense encoder \cite{chen2024bge} querying a 1024-dimensional HNSW index in Qdrant, and an asynchronous reciprocal-rank fusion engine \cite{cormack2009rrf}.
    \item \textbf{Node~C (Edge Ingress \& Sparse Node):} An independent edge machine deployed in three-node campaigns (\S\ref{sec:generalization}) running client ingress and local Tantivy sparse search.
\end{itemize}

\subsection{Placement Topology Taxonomy}
We define five candidate placement configurations based on where the network boundary bisects the pipeline (Figure~\ref{fig:topologies}):
\begin{itemize}
    \item \textbf{P0 (Colocated):} All stages execute on Node~A.
    \item \textbf{P1 (Edge Gateway):} Query ingress resides on Node~B; all retrieval, hydration, and generation execute on Node~A.
    \item \textbf{P2 (Split Retrieval Baseline):} Sparse and dense retrieval and RRF fusion execute on Node~B. Only top-$k$ document identifiers (144 bytes for $k{=}10$) cross the link to Node~A, which executes hydration, prefill, and autoregressive decoding.
    \item \textbf{P2-SPHP (Speculative Split):} Augments P2 by transmitting an early provisional sparse hint (104 bytes for top-5 IDs) to Node~A immediately upon sparse completion to trigger masked prefill.
    \item \textbf{P3 (Edge Hydration):} Hydration executes on Node~B, transmitting the full text of passages ($\approx$6~KB) across the WAN.
\end{itemize}

\subsection{Network Control \& Measurement Protocol}
To model WAN links faithfully, we apply Linux \texttt{netem} \cite{netem2024} \emph{bidirectionally} on Node~A: outbound packets are delayed by $\mathrm{rtt}/2$ via an egress qdisc, while inbound packets are redirected to an intermediate functional block device (\texttt{ifb}) and delayed by $\mathrm{rtt}/2$. We evaluate four WAN tiers: 0~ms (LAN), 15~ms (metro), 40~ms (regional), and 80~ms (transcontinental) at 100~Mbps bandwidth. Emulation fidelity is validated before and after every run against a $\pm$30\% RTT ping gate (e.g., 14.3~ms measured at 15~ms target) and a $\pm$0.05~pp loss readback gate; all gates passed.

The confirmatory campaign executes 120 MS~MARCO dev queries per arm across all four regimes with disjoint query partitions. Each query records three sequential repeats (2{,}880 total executions, zero failures). Repeat~0 represents a \emph{cold-prefix} reference state under a resident engine; repeats 1--2 capture the \emph{warm} steady-state. Confidence intervals (95\%) are derived via 2{,}000 bootstrap resamples.

\textbf{Retrieval leg asymmetry and the TTFT budget.} Table~\ref{tab:latency} summarizes the stage latency breakdown for baseline P2. Warm sparse retrieval requires 68--89~ms, whereas dense retrieval requires 111--118~ms ($1.3$--$1.6\times$ asymmetry). In the cold state, sparse traversal requires 576--640~ms (dominated by OS buffer page faults), while dense encoding and search require 1{,}029--1{,}130~ms ($\approx$1.8$\times$). Crucially, the parallel retrieval barrier ($\max(\Tsparse, \Tdense)$) consumes only 111--131~ms of warm TTFT (510--588~ms). The \emph{prefill residual} (passage hydration, tokenization, transformer prefill, and internal queueing) constitutes the dominant term: 392--464~ms warm. Consequently, optimizing network transit cannot yield major savings; instead, latency acceleration must target overlapping the prefill residual.

\textbf{KV-cache state dominates WAN network latency.} The latency gap between cache states in Table~\ref{tab:latency} dwarfs network variation: cold TTFT ($1{,}656.8$--$1{,}720.0$~ms) is $2.8$--$3.2\times$ warm TTFT ($510.0$--$587.6$~ms) across all tiers. Across the 0 to 80~ms RTT sweep, warm TTFT increases by only 77.6~ms (slope $\approx$0.95~ms/ms), exactly reflecting a single WAN crossing for identifier payloads. Cold TTFT remains statistically flat across network tiers. Decode throughput remains constant at 35.2--35.5~tok/s. These empirical findings indicate that systems assuming network delay is the primary driver of geo-distributed RAG latency misdiagnose the bottleneck: KV-cache warmth governs performance.

\section{The SPHP Protocol}
\label{sec:sphp}

\begin{figure*}[t]
\centering
\includegraphics[width=0.74\textwidth]{figures/fig3_sphp_timeline.pdf}
\caption{SPHP execution timeline at RTT=40~ms, BW=100~Mbps. (a) Baseline P2 fully serializes retrieval, fusion, WAN transfer, and prefill. (b) Under SPHP, completion of the sparse leg immediately triggers a provisional hint message. Node~A executes masked speculative prefill in parallel with the in-flight dense leg and RRF fusion, emitting the first token immediately upon verification.}
\label{fig:sphp}
\vspace{-2mm}
\end{figure*}

\subsection{Protocol Specification}
SPHP (Speculative Progressive Hydration \& Prefill) pipelines retrieval and generation stages (Figure~\ref{fig:sphp}). Rather than waiting for the dense leg and fusion to complete, SPHP exploits the temporal head start of sparse retrieval:
\begin{enumerate}
    \item \textbf{Provisional Sparse Hint:} At time $\Tsparse$, Node~B transmits the top-5 sparse passage identifiers ($\mathcal{H}$, 104 bytes) over WireGuard to Node~A.
    \item \textbf{Masked Speculative Prefill:} Node~A immediately hydrates $\mathcal{H}$ from local SQLite and initiates speculative prefill $\hat{P}$ on the LLM. The generated tokens are buffered internally and masked from the client stream.
    \item \textbf{Set-Overlap Reconciliation:} At $t_f = \Tdense + \Tfusion + \Twan$, the true fused ranking ($\mathcal{F}$, top-10 IDs) arrives at Node~A. Node~A evaluates the set overlap:
    \begin{equation}
        \text{Overlap}(\mathcal{H}, \mathcal{F}) = \frac{|\mathcal{H} \cap \mathcal{F}|}{|\mathcal{H}|} \ge \theta,
    \end{equation}
    where $\theta = 0.5$ (Algorithm~\ref{alg:sphp}). On a \emph{hit}, $\hat{P}$ is committed, the provisional KV-cache prefix is retained, and token emission begins immediately. On a \emph{miss}, $\hat{P}$ is aborted, paying penalty $\Tmiss$ (124.5~ms warm, 1{,}076.6~ms cold), and standard prefill executes on $\mathcal{F}$.
\end{enumerate}

\begin{algorithm}[t]
\caption{SPHP: Speculative Prefill Protocol}
\label{alg:sphp}
\small
\begin{algorithmic}[1]
\Require Query $q$, hint size $k_h=5$, final size $k_f=10$, threshold $\theta=0.5$
\State \textbf{Node B:} Launch sparse ($\Tsparse$) and dense ($\Tdense$) search in parallel
\State \textbf{Node B:} On sparse completion, stream hint $\mathcal{H}$ to Node~A
\State \textbf{Node A:} Hydrate $\mathcal{H}$ locally; begin masked prefill $\hat{P}$
\State \textbf{Node B:} On dense completion, compute RRF context $\mathcal{F}$; stream to Node~A
\State \textbf{Node A:} On $\mathcal{F}$ arrival, reconcile:
\If{$|\mathcal{H} \cap \mathcal{F}| / |\mathcal{H}| \ge \theta$} \Comment{Speculation Hit}
    \State Commit $\hat{P}$; begin streaming tokens to client immediately
\Else \Comment{Speculation Miss}
    \State Discard $\hat{P}$; execute standard prefill on $\mathcal{F}$; pay $\Tmiss$
\EndIf
\end{algorithmic}
\end{algorithm}

\subsection{Measured Acceleration and Quality Boundaries}
\textbf{Statistically significant TTFT reduction.} Across 120 queries per cell, SPHP cuts cold TTFT by 23.7\%--27.6\% across all four RTT tiers ($-24.1\%$ at 0~ms, $-27.6\%$ at 15~ms, $-23.7\%$ at 40~ms, $-25.5\%$ at 80~ms). All four one-sided permutation tests clear the Holm-FWER significance threshold ($p \le 0.0008$), with large effect sizes (Cohen's $d = -1.29$ to $-1.57$). At 0~ms RTT, cold TTFT drops from 1{,}656.8~ms to 1{,}258.4~ms ($-398.4$~ms). Across the entire campaign, the measured speculation hit rate is $h = 0.900$ (95\% CI $[0.883, 0.914]$), with mean document set overlap of 0.636 ($[0.629, 0.643]$).

\textbf{Bounded answer divergence.} Because hit-path responses are generated from the provisional sparse-only context, we quantify answer drift across 200 seeded dev queries. As a control, re-generating responses from identical fused contexts under baseline P2 yields a token-F1 of 0.586 (Exact Match 0.121) due to decode sampling stochasticity. Hit-path SPHP responses agree with the baseline at token-F1 of 0.422 (Exact Match 0.042). The semantic shift is bounded and comparable in magnitude to intrinsic sampling noise, while preserving the retrieval index untouched.

\section{Analytical Cost Model \& Policy}
\label{sec:costmodel}

\subsection{Closed-Form Placement Formulation}
We formulate an analytical cost model predicting TTFT as a function of payload size $p$, round-trip time $\mathrm{rtt}$, and link bandwidth $\mathrm{bw}$ (Mbps):
\begin{equation}
\Twan(p, \mathrm{rtt}, \mathrm{bw}) = \frac{\mathrm{rtt}}{2} + \frac{8\,p}{\mathrm{bw} \times 10^6} \times 10^3\ \text{ms}.
\end{equation}
Payload sizes are $p_{\mathrm{id}} = 144$~B (top-10 IDs), $p_{\mathrm{hint}} = 104$~B (top-5 hint), and $p_{\mathrm{text}} = 6{,}064$~B (hydrated text). Letting $T_{\mathrm{ret}} = \max(\Tsparse, \Tdense)$, the expected TTFT equations are:
\begin{align}
\Tttft^{(0)} &= T_{\mathrm{ret}} + \Tfusion + \Thydrate + \Tprefill, \label{eq:p0}\\
\Tttft^{(2)} &= \Tttft^{(0)} + \Twan(p_{\mathrm{id}}), \label{eq:p2}\\
\Tttft^{(3)} &= \Tttft^{(0)} + \Twan(p_{\mathrm{text}}), \label{eq:p3}\\
\Tttft^{(2,\mathrm{SPHP})} &= h \max(t_f, t_p) + (1-h)(\Tttft^{(2)} + \Tmiss) - C_{\mathrm{c}}, \label{eq:sphp_cost}
\end{align}
where $t_s = \Tsparse + \Twan(p_{\mathrm{hint}}) + \Thydrate$, $t_p = t_s + \Tprefill$, $t_f = \Tdense + \Tfusion + \Twan(p_{\mathrm{id}})$, and $C_{\mathrm{c}}$ is the cold credit ($64$~ms cold, $0$ warm).

\subsection{Regime Validation \& Uniform Crossover}
Parameters are fitted per cache state: warm $\Tsparse{=}79.2$~ms, $\Tdense{=}114.0$~ms, $\Tprefill{=}423.6$~ms; cold 603.2, 1{,}091.7, and 568.1~ms; $\Rdecode{=}35.3$~tok/s. We validate the model via leave-one-tier-out cross-validation across the four RTT tiers. The P2 model achieves \textbf{2.15\%} (cold) and \textbf{4.13\%} (warm) held-out regime MAPE (Figure~\ref{fig:parity}). The SPHP model achieves \textbf{6.42\%} cold and \textbf{4.37\%} warm MAPE.

Sweeping the model over RTT $\in [0, 200]$~ms and bandwidth $\in [10, 1000]$~Mbps (Figure~\ref{fig:crossover}) reveals that P2-SPHP is optimal in all 35 swept cells for both cache states. The warm-state advantage (2.8\%--3.4\%) and cold advantage (23.2\%) are invariant to network RTT because identifier payloads serialize in under 0.1~ms. Evaluating the model-driven policy post-hoc against the campaign (Table~\ref{tab:livepolicy}) selects P2-SPHP in every regime, tracking realized warm TTFT to a pooled error of 5.57\% (0.68\%--11.4\% per tier), directly answering RQ3.

\subsection{Robustness under Packet Loss \& Outages}
\label{sec:robustness}
\textbf{Zero errors under link loss.} We sweep bidirectional packet loss of 0.5\%, 1.0\%, and 2.0\% at 0 and 40~ms RTT ($n{=}50$ queries/arm; Table~\ref{tab:losssweep}). Across all 600 requests, zero transport errors occur. Cold TTFT reductions range from 22.6\% to 33.4\%, matching loss-free gains (23.7\%--27.6\%). Speculation hit rates remain resilient (0.80--0.90, pooled 0.857), showing that hint messages are robustly recovered by TCP.

\textbf{Dynamic edge fault recovery.} Evaluating edge node failure under a 365-request sequence with a 45~s forced service outage demonstrates clean recovery. In two-node edge failure (D-B), killing Node~B causes exactly two requests to exceed the 30~s timeout; service restores with Time-to-Recovery (TTR) of 86.5~s (45~s outage + 41.5~s initialization and warming), achieving post-recovery latency within 1.4\% of baseline (p50 1.86~s vs.\ 1.83~s) with zero post-recovery errors across 295 requests. In three-node failure (D-C), killing Node~C yields a TTR of 64.27~s, resuming post-recovery execution with zero errors at identical latency (p50 2.07~s pre- and post-fault).

\section{Multi-Topology Generalization}
\label{sec:generalization}

\textbf{Physical three-node tiering (CM-2).} We generalized the pipeline topology by enrolling a third physical machine (Node~C) as a dedicated edge sparse-retrieval and ingress tier ($P_3$). Node~C executes Tantivy BM25 locally, dispatches dense retrieval to Node~B over WireGuard, and speculatively pre-streams the sparse hint directly to Node~A. Evaluating across three WAN regimes ($B \in \{15, 40, 80\}$~ms with $C{=}15$~ms; $N=240$ queries/arm, 1{,}440 total requests, zero transport errors) confirms consistent acceleration: cold TTFT decreased by 16.9\% ($2{,}495 \to 2{,}073$~ms at $B=15$), 26.7\% ($2{,}784 \to 2{,}039$~ms at $B=40$), and 19.0\% ($2{,}522 \to 2{,}043$~ms at $B=80$), while warm TTFT dropped by 27.5\% ($1{,}404 \to 1{,}017$~ms), 24.5\% ($1{,}406 \to 1{,}062$~ms), and 28.8\% ($1{,}414 \to 1{,}006$~ms). Hit rates remained high ($h = 81.3\%$--$86.3\%$, overlap $0.608$--$0.630$). Furthermore, SPHP completely flattens warm TTFT sensitivity to Link~B RTT: baseline warm TTFT increases by only $9.9$~ms across a $65$~ms RTT increase (a slope of $0.153$~ms/ms), proving that multi-tier speculation immunizes users from multi-hop WAN delay.

\textbf{Live unshaped public WAN validation (CM-4).} To verify that \texttt{netem} synthetic emulation bounds production networks, we evaluated unshaped public internet routes ($N=50$ queries/arm, 200 measured queries, \texttt{netem} disabled). On the two-node public route (median TCP-connect RTT 1.10~ms, p95 4.07~ms), P2-SPHP reduced cold TTFT from 1{,}730.72~ms to 1{,}308.60~ms (24.39\% mean reduction, 28.0\% median speedup; $h=0.820$, overlap 0.600). On the three-node route originating from Node~C (median RTT 4.33~ms, p95 10.46~ms), SPHP cut cold TTFT from 2{,}624.11~ms to 1{,}997.29~ms (23.89\% mean reduction, 26.8\% median speedup; $h=0.840$, overlap 0.600), matching synthetic emulation gains (23.7\%--27.6\%) under authentic internet jitter and congestion.

\textbf{Asymmetric multi-leg stress matrix (CM-5).} To evaluate SPHP under hostile, lossy topologies, we executed the full 27-cell CM-5 stress matrix ($B \in \{15, 40, 80\}$~ms with independent per-leg losses of 0.5\%, 1.0\%, and 2.0\% on Link~B, Link~C, and both simultaneously; 54 arms, 810 measured queries, zero transport failures). SPHP-from-C achieved a mean TTFT reduction of \textbf{24.74\%} (median 24.83\%, peak 34.54\%), maintaining a mean hit rate of \textbf{86.91\%} ($h \in [0.667, 1.000]$) and document overlap of 0.624. Speedups remained uniform across tiers: 25.65\% at $B=15$~ms ($h=85.93\%$), 22.23\% at $B=40$~ms ($h=83.70\%$), and 26.33\% at $B=80$~ms ($h=91.11\%$). Under concurrent 2\% loss on both Link~B and Link~C at $B=80$~ms, SPHP achieved a 34.54\% TTFT reduction ($2{,}812 \to 1{,}841$~ms) with 100\% hit rate, proving SPHP is robust to multi-hop packet loss.

\section{Discussion \& Threats to Validity}
\label{sec:discussion}

\textbf{Systems design implications.} Our findings contradict the intuition that WAN placement is primarily constrained by transmission latency: when identifier boundaries are maintained, network RTT is a second-order factor, whereas KV-cache state swings TTFT by $3\times$. Distributed RAG engineering should prioritize cache warming and speculative prefill rather than link micro-optimization.

\textbf{Threats to validity.} (1)~\emph{Hardware specifics:} Dense retrieval ran on a GTX~1660~Ti; while absolute timings reflect this hardware, qualitative conclusions (prefill dominance, cache dominance, RTT flatness) hold across heterogeneous tiers. (2)~\emph{Model and corpus:} Measurements use MS~MARCO and a quantized Qwen3.8-27B generator ($\approx$35~tok/s); hit rates reflect lexical/semantic overlap distributions that may vary across corpora. (3)~\emph{Concurrency:} Tests evaluate single-query streams; multi-tenant queuing remains future work.

\textbf{Reproducibility.} All artifacts---including indices, testbed drivers, scoring pipelines, and analysis scripts---are released at \url{https://github.com/ApatheticMioz/geo-distributed-hybrid-rag}. Every figure and table regenerates deterministically from committed run files.

\section{Conclusion}
\label{sec:conclusion}
We presented a measurement study of stage-to-node placement for hybrid RAG across controlled and wide-area environments. KV-cache state dominates latency variance ($2.8$--$3.2\times$), whereas TTFT remains flat across WAN RTTs ($\approx$0.95~ms/ms sensitivity). SPHP eliminates prefill bottlenecks by speculatively overlapping masked prefill with dense retrieval, reducing cold TTFT by 23.7\%--27.6\% ($p \le 0.0008$, $h=0.900$). Our validated analytical cost model confirms that SPHP split placement is globally optimal. Empirical validation across physical three-node clusters, unshaped public WAN routes, edge failures, and loss stress matrices establishes that speculative prefill acceleration provides robust, self-healing performance across distributed topologies.
