### Why not executed (demonstrated, not assumed)

1. `scripts/netem/validate.sh` requires root: `FATAL: validate.sh must run
   as root (CAP_NET_ADMIN required).` — confirmed by invoking it
   (`bash scripts/netem/validate.sh --link-c 15` → that exact FATAL, rc=1).
2. The sandbox process has **no capabilities at all**
   (`CapEff: 0000000000000000` in `/proc/self/status`; raw ICMP socket
   creation denied with `Operation not permitted`) and `sudo` is blocked
   by the container's "no new privileges" flag
   (`sudo: The "no new privileges" flag is set, which prevents sudo from
   running as root.`). `unshare` / `nsenter` escalation attempts also fail
   with permission denied.
3. Therefore `tc qdisc` mutation (netem leaves) is impossible from this
   sandbox: `CAP_NET_ADMIN` is unobtainable here.

This is the same class of barrier as the `~/.ssh` permission artifact found
in the same run — a sandbox/uid artifact, **not** a defect in the (fixed)
scripts or a state problem on Node A.

### Host state verified pristine (before and after)

  egress only; **no netem, no htb, no ifb ingress mirror**.
- `ip link`: no `ifb0` device present.
- No repo script was modified in this run.

## Post-fix execution (privileged container, PING_COUNT=11)

**Executed:** 2026-10-12 17:52–17:53 UTC (host container timestamps in the
raw logs). This is the execution of the exact gate above that task d5fe0013
could not run: executed inside a **privileged, host-network Docker
container** (root + `CAP_NET_ADMIN`, `iproute2` + `iputils-ping` + `kmod`
installed, host `/lib/modules/6.18.33.2-microsoft-standard-WSL2`
bind-mounted read-only so `modprobe ifb` works against the host kernel) —
the same environment recipe that unblocked the A→B post-fix re-validation
(see `validation_ab_20261012T145653Z.md`, "Post-fix re-validation"). Only the
repo's own scripts (`validate.sh` → `apply.sh`/`clear.sh`, `show.sh`) were
executed; **no raw `tc`** was used outside what the scripts themselves do.
`validate.sh` runs with `PING_COUNT=11` (post-`7943cca`), so all medians
below are 11-sample.

All three tiers ran from a **true cold start** (ifb module not loaded; no
`/etc/modprobe.d` override needed — the `7943cca` idempotent ifb bring-up
held, confirming the precondition note above). Each tier: `clear.sh`
assertion → reachability check → 11-ping baseline → `validate.sh --link-c
<tier>` → post-gate reachability check → 11-ping restored baseline →
`show.sh`. **No tier required a re-run** (all PASS on attempt 1, within the
max-2-attempts budget).
